# Requirement — Use CAPRMADIO as the framework identity

The canonical framework name is **CAPRMADIO**. It expands to
**Concern–Analysis–Plan–Requirement–Method–Assurance–Delivery–Implementation–Ops**,
matching the nine governed Content roles.

The model may be presented as **CAP · RMAD · IO**:

- CAP is Concern, Analysis, and Plan;
- RMAD is the distributed Specification formed by Requirement, Method,
  Assurance, and Delivery; and
- IO is the native Implementation and its enacted Ops feedback.

The public outcome-oriented logline remains **The Vibe-Code-to-Production
Framework**. Public documentation, project metadata, repository identity,
package identity, installed methodology, and user-facing commands must converge
on CAPRMADIO through a governed migration. Historical evidence may retain prior
names and URLs when required for provenance.

## Primary claim

CAPRMADIO is the framework's canonical identity and expands to its nine Content
roles in `CAP · RMAD · IO` order.

## Rationale

The name exposes how the framework moves from a concern through analysis and
an accepted change plan, into a four-part specification, native realization,
and operational feedback.
