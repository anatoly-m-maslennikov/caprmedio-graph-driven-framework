Step: CA-O-094 | Action: CA-O-020 | Context: Integrated

selected Project, persistent Plan, R/D targets, full current Method SourceRows
(`methods`; optional legacy `method_projection` is not required), applicable E
Atoms, source revisions and hashes, candidate, permissions, retry state, and
retained evidence. Missing, stale, conflicting, incomplete, or unauthorized
input returns `blocked`.

- Bind checks to the exact candidate, governing R/D and M, E checks, fixtures,
  commands, and execution phase.
- For final checks require actual `preliminary_clear` evidence for this exact
  candidate and relevant source/test/input bindings. If it is missing or stale,
  return `blocked`, never `passed`. Initial pre-implementation baseline checks
  do not require preliminary clearance and must not claim final acceptance.
- Execute the admitted baseline, E2E/golden-corpus, and relevant targeted or
  regression checks. Preserve actual output, failures, blocked checks,
  coverage gaps, and stale results.
- Do not edit code, tests, expected outputs, authority, or retained evidence.
  Do not replace execution with remembered or mock-validator results.

Results: `passed` | `failed` | `blocked`.

Return the result, commands, candidate-bound evidence, coverage, retained
state, and blockers. `passed` requires complete current coverage with no
failed or blocked checks; diagnosis and routing remain caller-owned.
