# Install all FRAMEWORK_ENGINE Tools

`INSTALL_TOOLS` must be one Doer Tool owned immediately by `TOOLS` as an `unordered_unit` at Structural level `4`, addressed by `102_FRAMEWORK_ENGINE/201_PROGRAMMATIC/301_TOOLS/INSTALL_TOOLS`, and realized under `102_FRAMEWORK_ENGINE/201_PROGRAMMATIC/301_TOOLS/INSTALL_TOOLS/`. It must resolve every runnable Tool and shared implementation dependency from the canonical root `102_FRAMEWORK_ENGINE/201_PROGRAMMATIC/301_TOOLS`, publish one digest-verified content-addressed release under `.caprmedio_runtime/tools`, select that release through one machine-readable current manifest, and install every registered stable launcher and host Hook for the selected release. The Codex integration must merge one generic user-level dispatcher into the active Codex user Hook carrier while preserving unrelated Hook groups. The dispatcher must resolve the current repository at invocation time, require its installer-set local Git activation marker, and address its stable runtime-owned launcher rather than a repository-specific or content-addressed release path, so all Codex tasks can share one reviewed Hook identity without executing an unselected repository lookalike Carrier.

Installation must use dry-run unless apply is explicit, preserve pre-existing user-level Codex and default Git Hook behavior, reject an unrelated local `core.hooksPath` before mutation, migrate only recognized prior CAPRMEDIO project-local Hook carriers, keep persistent operational state under `.caprmedio_runtime`, and keep disposable staging, bytecode, cache, build, Evaluation, and atomic-write intermediates under `.caprmedio_tmp`. If a required host Hook carrier is unavailable, installation must fail with a stable diagnostic and restore the previously selected release and runtime-owned Hook fragment rather than leave a partially selected runtime. No executable Framework dependency may be installed into the Codex user directory. Installed Tools must remain runnable when the canonical source is not on their import path. Installation status must distinguish an installed Hook Carrier from host activation and must state when the host requires one Operator-controlled trust or review action that the installer cannot establish.
