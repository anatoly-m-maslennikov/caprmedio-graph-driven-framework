## Summary

Interactive HTML graph view behavior

## Claim

### Prose Claim

Exercise the generated MRT through its real declared Workbench query contract. It renders the selected current graph and requested indexed Atom Content without becoming another authority surface.

## Details

- Use multiple declared Scope Units and current indexed Requirements with connected RMED neighbours. Materialize exactly one `_projection/mrt_atoms.html` under the selected Project’s declared authority root with embedded JavaScript and presentation assets; require no sibling web assets or per-Atom files. Open the generated asset through the selected Workbench listener and verify its query requests stay on that same origin, without file-origin API access or a separate server.
- Verify the manifest records the selected query/source bindings and each consumed Atom reference, Version, relative location and public row hash. Graph placement and direct/derived edges match the selected read-model state. A row hash is not labelled as a source-byte digest.
- Change the declared Scope structure and verify the filter tree changes without hard-coded Scope names. Exercise Tier, Scope Unit, Content Role and Form filters, plus orphan/cycle controls. A hidden neighbour does not create an orphan.
- In short mode, verify the authored Summary label, indexed Content on first click and available indexed Header on second click. In detailed mode, verify Content initially and Header on click. Indexed Content is not falsely labelled as complete raw source bytes. Untrusted content remains inert data.
- Change an indexed Atom or available synchronization state after generation. Verify the interface distinguishes a stale rendered view, changed row and unavailable data using returned evidence. Missing freshness metadata does not become proof of freshness. No raw-file endpoint or legacy STG registration is required.
- Preserve filters and focused identity in the URL. Removing the MRT changes no Atom, Journal, other Projection, Workbench, Tool or MCP capability.

Reject a build or interaction that omits selected nodes/edges, loses required controls or Content, invents lineage/freshness, escapes the selected Project/service contract, or modifies authority. Keep the preceding valid derived view when a replacement cannot be built. Terms Graph construction and native Codex-plugin acceptance remain deferred.
