## Summary

Carry code-owned MCP registration in the installed package

## Claim

### Prose Claim

The MCP package carries tool_providers.json as its code-owned provider and selected-route inventory, generate_tool_registry.py as its generator, and tool_registry.json as its generated runtime registration asset, all in FEATURE_MCP.

The generator accepts --package-root and reads the inventory and installed provider code, without reading Project Atom carriers. Equivalent installed inputs produce equivalent asset bytes. Provider registration uses the existing canonical descriptor, models and adapter symbols; it does not execute a capability during generation.

Generate the asset inside the staged local-release package before its final inventory verification and candidate-image build. Include the generated bytes in that package identity. Regenerate the same asset after engine code is copied during an image rebuild. Generation failure stops that build or release before MCP startup. Direct source development uses the same generated asset and generator.

The post-readiness tools_catalog.json remains a discovery output built from the actual MCP tools/list response. It is not the executable registration input. Do not add a daemon, watcher, Workflow scheduler or source-Atom fallback for registration.
