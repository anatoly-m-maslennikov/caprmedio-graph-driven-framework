# Legacy MODEL subject triage

`manifest.json` classifies each of the 74 publication-audit flags and pins the audit, decision record, cited current sources, and selected current authorities. All 384 referenced source files match their audit hashes and every recorded subject string remains in its corresponding file. These are source checks, not a fresh projection or an assertion that each Claim is correct.

The classes are triage dispositions: 10 legacy, 50 ambiguous, 14 Term. A legacy classification identifies an obsolete model expression, not permission for mechanical replacement. Term means the missing Declaration diagnostic alone is insufficient: inspect the applicable Method/Term Definition and the particular meaning; it does not validate every historical Entity-rooted term address. Ambiguity includes possible inherited coverage, but inheritance is not inferred without an exact declaration and path. There are no asserted true gaps on this evidence. Source revisions and retirements remain proposals; no candidate preview is provided because individual Claims and active-subject scope require adjudication. Hence no candidate hashes are claimed. Frozen references, IDs, summaries, versions and timestamps have not been changed.

## First decision

Should CA-R-1990 and CA-R-1991 be revised to state their existing Plan→Plan and Workflow→Step containment permissions in terms of the child's `Atom.Header.Relations.IS_CONTAINED_BY`, removing the obsolete `Enabled Relations.Contains` property? The current declaration CA-R-2698 stores that relation on the child. The two rules currently make a Boolean capability mandatory and then say containment is permitted; CA-R-1991 also has a passive `Workflow >{1+} Step` expression. Replacing a property with a relation mechanically could change capability into a requirement to have a child or parent, or change the scope selected by the active Subject. The decision affects these two rules and their consumers; the existing Workflow cardinality expression must be reconciled separately rather than silently altered. If accepted, draft exact revised Claims and active/passive Subjects for review, preserving the distinction between permitted containment and required instances.

Dependent Entity and Type need meaning-level review; the existence of a component word is not a declaration of a model entity.

CA-R-2464 requires a Workflow instance to contain one or more Steps. CA-R-1991 overlaps that requirement, but its retirement requires consumer/reference review. CA-R-2511 contains a conditional parent requirement for ordered active Plans, not an explicit permission for Plan-to-Plan containment; CA-R-1990 has additional permission semantics. Whether and how those Plan permissions belong in the Declaration remains unresolved. Do not infer an automatic inverse.
