# Property contract review

The 87 Property targets recognized by the prior postcheck were reviewed against their live Requirement/Form Declaration Claims and the selected enclosing contracts. `property-contract-review.tsv` records, for each, the source version and SHA-256, direct-value format/count, named occurrence bound, direct-child name selection/count, recursive constraint and relevant enclosing Declaration IDs. `property-evidence.tsv` retains the source Claims. The table also includes the newer CA-R-2733@1 Workflow.Purpose as an explicitly separate pending item; its decision belongs to another lane. CA-R-2734@1 and CA-R-2735@1 are Current selected Workflow variants, not Property declarations.

The selection is the earlier post-migration frontier refreshed by reading live files, not a complete census: 47 selected paths drifted from that frontier's historical hashes. Each reviewed Property source is pinned to its live hash. Review of exact listed clauses and known enclosing contracts found no value-format or direct-name-count contradiction warranting a prospective fix. The 87 rows do not prove absence of every unsupported or unrecognized selector elsewhere. The prior extraction has complex Subjects and unresolved candidates; they are not automatically new Properties or established conflicts.

## How to read the table

CA-R-2243@11 (SHA-256 `94064ca20c258b8d79b7fabf1071b093395c4b4a3b8e6d9ffd85270818dd718e`) distinguishes property occurrence, direct values of an existing property, and counts of dependent names; an omitted annotation is unspecified. `.*[]{:0}` means no declared immediate dependents after local and inherited resolution, not zero values. `.**` recursively counts selected distinct descendant names; a value constraint after it applies to selected descendants. A wildcard does not create a new Property. Ordinary Markdown headings in Prose Claim do not become Properties.

CA-R-2470@2 (`1a0c6184a19e884324edf2b614045970babea2824bee85d911553acc2bb53093`) and CA-R-2475@5 (`131cef35b89473fb12fdc08e5cbc4d2a1718f67aea49fdeb410c24dd0920ce7c`) establish inheritance through narrower kinds, without cloning a Property or treating dependent paths as narrowing. Enclosing context in the table identifies the applicable parent or recursive constraint, not a claim that dependence itself is inheritance. CA-R-2524@3 declares Project narrower than Scope Unit, so Scope Unit properties are inherited by Project without redeclaration; CA-R-2553 declares Implementation narrower than Package and CA-R-2555 constrains its inherited structural level. Qualified Atom role selections receive the applicable base Atom constraints; their role-specific Properties are admitted by CA-R-2719@1. Context IDs resolve to source versions and hashes in the evidence table where they are among the reviewed 87.

## Material results and limitations

- CA-R-2500@4 requires the RMED Claim container with zero direct values and specifies one or two Formal Claim/Prose Claim names; each present child carries one Markdown value. Its Prose Claim explicitly calls for at least one of these children. CA-R-2498@4's recursive Markdown 0..1 value constraint is compatible with the zero-valued container and each one-valued child. CA-R-2721/2722 provide matching child declarations.
- CA-R-2717@2 and CA-R-2718@2 state the accepted model-level Name and Path direct-value clause as `[string]{:1}` with no pre-colon occurrence count. CA-R-2716@1 selects two child names. Under CA-R-2243, the child-name count and value count are not themselves a named-occurrence annotation; retain the separately communicated mandatory Name/Path meaning without adding a second pre-colon occurrence annotation or inferring syntax not supplied.
- CA-R-2702@1 has one string Role value and does not duplicate the role value registry; qualified Role declarations and CA-R-1283@33 apply in their contexts.
- Five of the existing 87 Claims omit a named occurrence bound in their own direct-value clause: Name and Path above, and Scope Unit.order, order.ordered and order.number. The latter has a conditional integer-one/zero-value clause, not a declaration that its named occurrence is forbidden when false. CA-R-2687 constrains selected direct names to 1..2. Do not invent occurrence bounds from value or name counts.
- For the 87 selected property targets, no literal zero-immediate-dependent clause was found to have another recognized direct Property target beneath it. This is a bounded comparison, not proof over the unresolved and complex selectors or every narrowing path.
- CA-R-2733@1 is a separate newer Property: its `[string]{:1}` clause has no named occurrence annotation. CA-R-2464@5 and CA-R-2734/2735 provide variant context. Its outstanding question is handled elsewhere and does not change this review of the prior 87.
- Retired Carrier internals are not restored as Core Properties by physical Delivery mappings. No M/E/D is used as MODEL contract authority.

No prospective `.txt` source changes are supported by these bounded findings. Further semantic resolution is needed before making a global completeness claim, especially for unresolved/complex Subjects, broad or conditional selectors beyond the listed Claims, and inherited contexts not enumerated by the earlier extractor.
