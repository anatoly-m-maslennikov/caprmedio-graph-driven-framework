## Summary

Use Subject Path Separators for Broader-to-Narrower and Bearer-to-Dependent

## Claim

### Prose Claim


a Entity Path.


In a Subject expression, `X//Y` selects Y as a narrower kind of X and `Whole/Part` expresses immediate containment. `.` addresses a dependent Property. A named instance is selected with `$x[<Kind>, (conditions)]`; an anonymous instance uses `$<Kind>`. `:=` expresses HAS_ALLOWED_VALUE or qualified Subject selection; `::` expresses HAS_VALUE_CONSTRAINT. A bare qualified address refers to its declared target and declares no target. Parentheses provide logical grouping.

`Whole/Part` expresses immediate containment. Its direct fact is Part IS_CONTAINED_BY Whole, and CONTAINS is derived. `X >| Y` and `Y |< X` are opposite writings of the same
HAS_CLASSIFICATION fact, with Entity Y used as an applicable Classification
axis rather than belonging to a separate Classification Entity kind. This Rule does not
invent an inverse canonical Relation Type for HAS_CLASSIFICATION.

`X//(.Y := Z)` denotes a narrower kind of X qualified by its own Property Y
and value Z. The leading dot inside parentheses is relative to X: `.Y`
addresses `X.Y`. The qualified X inherits X's applicable features and
constraints. The Property is the qualification condition; it does not become
a narrower kind of its bearer. This form does not create a Property kind or admit a value without its governing authority.

`Source ((RELATION_TYPE)) Target` expresses a defined named Relation. Persist
the direct fact once and show its declared derived inverse only as a derived
view. Entity syntax neither creates target identities nor admits native facts
without defining authority. A defining Atom may introduce its governed Entity.

Cardinality uses `{::n}`, `{::n+}`, and `{::n..m}`. Direct Property values use
their post-Property notation, for example `X.Y:: [format]{::n}`. A Relation has two
independent directional slots: `Source {forward-count}RELATION{reverse-count}
Target`. The pre-operator slot constrains Relation instances in the written
Source-to-Target direction per Source; the post-operator slot independently
constrains the reverse count per Target. These are not distinct-target counts. For example, an admitted Step has exactly one outgoing IS_CONTAINED_BY link to either a Workflow or another Step; that bound leaves the reverse count unspecified.
`Property {::1}((IS_PROPERTY_OF)) Bearer` requires
exactly one outgoing IS_PROPERTY_OF Relation for each Property occurrence;
postfix-only `{::1}` would instead constrain the reverse count per Bearer.
Each Relation is binary and has the endpoint domains specified by its Declaration. HAS_ALLOWED_VALUE and HAS_VALUE_CONSTRAINT may address literal values or value constraints without creating literal Nodes.
The slots count Relation instances, not Relation arity; omitted slots remain
unspecified. This Relation counting is independent of the Property's
direct-value Format and cardinality.
Advanced expressions are governed by their applicable CFEL rules; this Rule does not independently define them.


```text
Atom//(.Header.Role := Method)
Source ((RELATION_TYPE)) Target
```


Applicable HAS_ALLOWED_VALUE alternatives, including inherited alternatives, combine by OR; HAS_VALUE_CONSTRAINT restrictions, including inherited restrictions, combine by AND. Final admissibility is `(HAV := #1 OR #2 OR ...) AND (HVC :: #1 AND #2 AND ...)`. When no allowed-value group exists, omit it (true); there is no enumeration restriction.

## Semantics

`//` is specialization and supplies inheritance. `/` is containment and does not supply inheritance, sequence, or a Property Relation. A typed participant selects an instance; `.` addresses a dependent Property. `:=` expresses an allowed value and `::` a value constraint, without assigning an occurrence. A bare qualified address refers to its declared target and creates neither an alias nor a duplicate.

`X.Y` addresses Property Y, and `X.Y := Z` expresses its allowed value.
`X//(.Y := Z)` instead identifies qualified X entities. For example,
`Atom//(.Header.Form := Method)` means an Atom with the stated Form qualification, not
the Form Property inheriting Atom's features. This syntax example alone does
not admit Method as a Form value; the existing Role use is written
`Atom//(.Header.Role := Method)`. Every qualification still requires its own
admitted Property and allowed value. Existing Carrier keys and encodings
remain governed separately by Delivery; the notation adds no nested object.

Status Group classifies Atom Statuses through `Atom.Header.Status >| Status Group`. The Draft group contains Draft and the Archived group contains Archived. The Current group contains admitted Atom Status values other than Draft and Archived. It does not admit new Status values, missing
values or a general expression language. Containment does not imply
inheritance; the Property-qualified Atom kind inherits through `//`.

## Details

Each Module belongs to exactly one Package; Project Implementation is the
parentless root Package and a nested Package belongs to another Package. A Step
is contained by a Workflow or another Step. Scope Unit has structural
parts expressed as `Scope Unit/Scope Unit`, `Scope Unit/Atom`, and
`Scope Unit/Projection`.

Backslash escapes the next literal name character in a Subject path. Double quotes delimit literal text when needed; they do not delimit an Entity path name segment. One globally unique primary
kind name and one canonical declaration path are required; migration does not
retain aliases. Term-path reconciliation remains subject to C605.
