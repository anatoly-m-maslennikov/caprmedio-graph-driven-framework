# Endpoint kinds and legacy MODEL bindings

The selection is `property-instances-20261104/post-application-frontier.json`, not the full repository. `authority-pins.json` pins the live versions, paths and SHA-256 of key declarations and Rules. `manifest.json` pins 98 prospective whole-file previews, their exact subject substitutions, original hashes and resulting hashes. No Current file was edited. Validation parsed every preview's YAML, verified pinned hashes, and checked that its body and all metadata outside `subjects` are byte-for-byte unchanged.

## Endpoint authority

- CA-R-2589@2 and CA-R-2590@2 declare `Node/Continuant` and `Node/Occurrent`; both branches remain in the model. CA-R-2542 declares Actor narrower than Continuant. CA-R-2523 declares Scope Unit narrower than Continuant; CA-R-2524 declares Project narrower than Scope Unit. CA-R-2525 declares Package; CA-R-2553 declares `Package/Implementation` as the root implementation Package. CA-R-2557 declares Event Record as a Continuant and distinct from what it records.
- CA-R-2464 declares Workflow as an Operations selection. CA-R-2733 declares its Purpose Property; CA-R-2734 declares the Runtime-Purpose Workflow variant. The word Runtime in this selection is a Purpose value; it does not establish an independent Runtime kind.
- CA-R-2245's Relation Declaration identifies Workflow Run as the actual host and Workflow as the reusable definition. CA-R-2246 identifies Event Record as the host and an actual occurrence as target, with Workflow Run one example, explicitly not the only one. CA-R-2255 identifies Runtime and Workflow Run as host and target. These Relations do not themselves declare either endpoint kind or any actual link. Their `$workflow_run`, `$runtime`, and `$occurrence` variables do not establish kinds.
- CA-R-1520/1525 govern Workflow Run behavior and exact definition revisions; CA-R-1528 governs Tool-call evidence within Step Runs. These are Rules, not Requirement/Form Declarations for Workflow Run, Step Run or generic Execution. A normal use of “execution” can describe an activity without establishing a kind. No native active Declaration of Workflow Run, Runtime, Execution or Event was identified in the earlier endpoint scan. The scan's scope is bounded; it does not prove none exists outside it or that populations are empty. An Event Record is not by itself evidence of a distinct Event kind.

## Preview scope

The 98 previews are review artifacts only. **Hold all 56 previews containing a Framework Settings replacement**: CA-E-671@1 and CA-R-1750@41 distinguish Project initialization Settings from Framework Instance Settings and assign behavioral choices to the latter. The user decision that Project settings are Properties does not alone establish that every legacy Framework Setting has the same meaning as a Project Property. Every mapping needs source-by-source meaning and exact Declaration review. The manifest marks these files HOLD. The remaining 42 files are candidates for review, not approved adoption. The proposed replacements are:

- Held: 56 occurrences of legacy `Project.Framework Settings` and 21 occurrences of names matching declared settings descendants are proposed as `Project.Settings` and the matching descendant. Project is a Scope Unit; Settings is a Property of Project, not a separate primary kind. Even matching names need meaning review. Unknown legacy descendants, including Parameter Resolution, Identifier, Tool Selections and Extension Selections, are held for individual mapping.
- 22 `Project Implementation` bindings become `Package/Implementation`; 27 old Journal/Event Record bindings become `Event Record`; CA-R-2245's legacy Workflow form binding becomes the currently declared Workflow selection.
- CA-R-1429 and CA-D-333 are held because replacement would duplicate an existing passive binding. They require an explicit duplicate-removal review. The counts above are replacements in generated previews, not a statement of applied changes.

The model Declaration establishes Actor but no current narrower Operator or AI Agent Declaration was identified. Their old paths occur in 119 and 26 selected sources respectively; changing either to bare Actor would erase a meaningful distinction, while inventing narrower kinds or concrete instances would assume a decision. AI Agent.Permissions is also not automatically established by Actor. Other Package subtypes, governing objects, Scope Unit/Project legacy properties and old occurrence paths remain unresolved unless exact declared identities and meaning are demonstrated. The preview mapping does not blindly strip `Continuant` or `Occurrent`.

## One prioritized decision

Which execution concepts should be explicit MODEL kinds, and how should Workflow Run, Step Run and Runtime relate to Occurrent (including whether Event or generic Execution is itself a kind)? This decision controls R2245/R2246/R2255 endpoint binding, the active Workflow Run and Step Run Rules, and the handling of record targets; it must not be inferred from untyped variables or ordinary prose. A separate Actor classification is still unresolved and should not be collapsed into the execution decision.
