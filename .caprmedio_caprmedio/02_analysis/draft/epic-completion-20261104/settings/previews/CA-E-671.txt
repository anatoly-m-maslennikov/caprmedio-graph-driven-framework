## Summary

Validate settings boundaries and Scope Unit Declarations

## Claim

### Prose Claim

Settings resolve inside their own Project without cross-Project fallback. Project Settings own the Project initialization inputs and applicable CAPRMEDIO behavior and configuration choices. A declared Scope Unit remains visible when its Carrier or active Goal is missing. An undeclared folder remains an observation. Scope Unit Declarations do not change Settings, and Settings do not replace a Declaration. No Projection edit changes Settings, Scope Unit Declarations, or source Atoms.

Every Framework Instance's Methodology Sources and Applicable Methodology output resolve beneath its own Project's `000_CAPRMEDIO_framework/` directory. Rebuilding one Project's Applicable Methodology does not read, replace, or modify another Project's sources, Settings, or compiled results. A missing selected Project instance is reported rather than resolved through another Project or the former repository-shared framework root. Nesting the framework directory does not change source Atom identity or make a Projection a second authoritative Atom.

## Details

### Test case

Create two Projects in one repository, each with Project Settings and a `000_CAPRMEDIO_framework` directory. Resolve each Project's Settings before creating its Project Atoms or Implementation. Give the instances distinct Methodology Sources and Applicable Methodology results. Declare a Scope Unit with no active Goal and no directory; separately add an undeclared candidate directory. Include Draft and archived Goals as non-active evidence.
