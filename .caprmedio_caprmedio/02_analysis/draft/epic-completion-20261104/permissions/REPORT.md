# Relation permissions — candidate source changes

Two full Current-source previews add named outgoing permissions in the relevant active-Subject contracts. Formal Claims state outgoing bounds using the existing target-omitted named Relation cardinality form; Prose Claims retain endpoint and qualification conditions. The form is already present in R2462, and R2465 uses target-omitted Relation counts. R2486 assigns endpoint domains to Relation Declarations; target-omitted counts do not expand those domains. No unbound generic endpoint variables or new CFEL constructs are introduced. Source, candidate, evidence and requested post-application frontier are pinned in `manifest.json`; recheck before integration. Summary, identity and metadata are preserved.

- R2508 applies to Atom: 0..1 HAS_ACTIVE_SUBJECT to its resolved active Subject and 0..1 GOVERNS to its actual governed Subject. R2714 separately requires one active Subject for Current Atoms; R2618 supplies the canonical link from that field. R2100 already limits GOVERNS to 0..1. Neither permission restricts targets to Node, confers authority on a Subject, or grants inverse directions.
- R2462 applies to Node: each logical model Node or Node Property has exactly one outgoing qualified IS_DECLARED_BY view to its canonical declaring Atom, consistent with R2278's effective-MODEL ownership invariant and R2732's qualified GOVERNS derivation. This model-entity permission does not apply a declaration ownership obligation to runtime instances, grant GOVERNS permission in reverse, or add a stored fact. Existing incoming HAS_ACTIVE_SUBJECT count in R2469 is unchanged.

The new clauses intentionally retain each target's semantic condition and do not weaken the outgoing wildcard for unrelated relations. Unresolved active-Subject resolution remains a diagnostic. They establish source-level permissions only; formal unary-whitelist extraction, endpoint-domain matching and evaluator support require verification, as does integration with other source edits. No canonical source, runtime, or Git state was changed.

R2508 Semantics uses Object in place of Artifact, following the latest user distinction that Artifacts are files/folders and Objects are model-entity instances, and the Current Carrier Declaration R1958. No change to the model of an Atom is inferred beyond that terminology correction.
