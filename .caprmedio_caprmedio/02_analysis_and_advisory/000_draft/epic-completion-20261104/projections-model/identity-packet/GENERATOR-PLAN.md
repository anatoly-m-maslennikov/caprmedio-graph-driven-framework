# MODEL view root binding and generator plan

The seven current MODEL views CA-PROJ-020 through CA-PROJ-026 are scoped to the Project root of caprmedio. The native root declaration CA-R-2640@1 has active Subject `CAPRMEDIO_STRUCTURE <+ Project//caprmedio` and declares `Project//caprmedio.Name == "caprmedio"`. Current CA-R-2524 declares Project narrower than Scope Unit. A read-only run of `read_scope_unit_declarations` with the repository root and `.caprmedio_caprmedio` control root returned exactly that root declaration, name `caprmedio`, and `is_root == True`; its `by_name` index resolves that root. The manifest pins the declaration, parser, resolver and generator hashes. The proposed stored reference is `Project//caprmedio`, not a fabricated Scope Unit identifier or a value derived from a filename. Implementation must verify that the typed Scope Unit reference accepts a Project instance under the current subtype semantics.

After MODEL packet approval and canonical Declaration ID allocation, implement and validate in this order:

1. Resolve the single Project root using the existing declaration reader and assembly checks. Bind each generated view to that resolved Project instance; if discovery fails, finds more than one root, or cannot resolve the declared Project Subject, fail without publishing. Do not derive the binding from display name, ID prefix, filename, or a configured fallback.
2. Assign each VIEWS row its distinct admitted Form matching its view name: Primary Entities Tree; Primary Entities with Direct Properties; Primary Entities with Inherited Property Contracts; Primary Entities with Inherited Formal Claims; Passive Only Subjects; Subjects without Requirement Declarations; Entity Definition and Active Subject Coverage. Preserve existing IDs only after checking that each `(Form, root Scope Unit)` and ID pair is one-to-one within the whole affected registry.
3. Update generated headers to carry `form` and `scope_unit: Project//caprmedio`, retaining `source.named_selection` as descriptive source information and `source.atoms` with exact versioned source pins. Output filenames reflect the Form but remain Carrier addresses, not identity sources.
4. Update `output_predecessors`: it currently checks the old literal `Map` and treats Named Selection as an identity condition. Replace those checks with ID plus resolved Form and Scope Unit, while independently validating Named Selection and source pins. Handle old filenames and metadata through a separately reviewed migration plan; do not bypass the existing guard against a second Carrier, symlinks or hash changes.
5. Add focused checks for unique-root resolution and missing/ambiguous-root failure, subtype reference compatibility, both identity directions, seven distinct Forms and IDs within the shared root, stability across source Version and Named Selection changes, changed identity on Form or Scope Unit change, and safe legacy-carrier migration. Rebuild and publish only after the source packet and migration are reviewed.

No generator, Current Projection, runtime, or historic Carrier is changed by this plan. Terms Graph remains deferred.
