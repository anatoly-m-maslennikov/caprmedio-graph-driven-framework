# Remaining Project Settings sources

Six pinned previews map the selected source topics to the declared Project.Settings or Reporting Mode Property. No new Property is introduced. CA-R-1629 preserves priority-conflict modes; they are not the strict/casual Authority Modes. CA-R-1631 preserves default-inactive optional Projection activation and unknown-type rejection. CA-M-279 and CA-E-450 retain default fallback, falsy explicit values, validation failure, unresolved required values, absent optional values and non-writeback. Their Parameter Resolution subject is an activity about the existing Settings Property, not a new Property. Default Settings physical ownership remains with the carrier lane.

CA-M-277 and CA-M-278 use the existing Reporting Mode Property and Subject `:=` selected values. Their silent and verbose values rely on CA-R-1628 and its concurrent Settings preview; target-resolution validation remains required after integration.

CA-R-1404 has a changed Summary and needs a new-ID successor. The supplied successor Draft preserves the non-Atom Property distinction. Allocate the ID and reconcile Current inbound references, notably CA-R-1981's evidence, before retiring the predecessor. Keep all exact historical references and archive history; the existing reference to CA-R-1402@27 is frozen.

CA-D-387 is coordinated with the carrier lane: it specifies `[artifacts].creation_strictness`, not a declared Property, and CA-R-1630 governs its medium/high semantics. Do not manufacture a Property or replace the carrier lane's source.

The undeclared Identifier Subjects in CA-D-358/362 concern competing legacy Carrier identifiers. Carrier-lane reconciliation and CA-R-1981's old Summary are required before changing or retiring them. CA-D-392's `project.obsolete_names` carries an explicit prior-names behavior; it is not supported as a field-only retirement. Does the Project still need to retain prior names, or is that behavior to be retired? If retained, establish its canonical authority and encoding before replacing its unresolved Subject; do not invent a Property by name.

All files here are previews, not Current changes or evidence of a runtime migration. The preserved generic fallback behavior may need a later carrier-specific merge; recheck pins and combine any overlapping edits before application.
