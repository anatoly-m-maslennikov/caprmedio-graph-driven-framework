## Project Settings parent and sibling check

`CA-R-2532@8` requires one zero-direct-value Project.Settings group with 3..11 selected child names from its eleven declared siblings. Name, Prefix, and AI Agent Confidence Threshold each have one required value (CA-R-2533@2, CA-R-2534@2, CA-R-2564@2), so the lower bound is already met when all optional siblings are absent. Optional groupings or settings are not forced by the parent count.

Shared formats remain compatible with local values: Authority Modes supplies string to its two required strict/casual children (CA-R-2632@3 through CA-R-2634@1); Confidence supplies int to its two optional threshold children (CA-R-1979@16, CA-R-2624@2, CA-R-2625@2). The other Settings siblings keep their local formats and counts: Artifact Timestamp Timezone and Framework Control-Root Locator are optional strings; Code-Root Locators is explicitly optional with one-or-more strings when present; Interaction is optional with one required Reporting Mode child; Implementation Retry Limit is optional int; RMED Review leaves retain their own float/int value bounds. No mandatory shared format conflicts with the parent count or a sibling's declaration.

## Project-root Goal Tier and ownership decision

The latest user predicate is explicit: any Atom with Form `Goal` whose active Subject resolves to the Project Scope Unit root carries exactly Tier `-1`. The predicate does not depend on a `Project Goal` Type or an ownership relation. The revised `CA-R-2132.preview.txt` applies that condition, removes Operator ownership, and retains explicit Tier `-1`. It keeps the existing Summary because it still describes the Tier rule. No other Goal receives a special Tier rule.

Connected RMED sources are aligned to the same predicate. The R2149 preview uses the resolved Project as ordering context without owner assertions; R2424 preserves its independent Tier-zero contract and uses the exact Form/active-Subject predicate for Tier `-1`; R808 retains all ordering domains and the Project Configuration prerequisite. M438 no longer resolves an Operator owner; it and E654 state directly that ordinary Scope Unit-owned Atoms use `>=0` except the exact Form Goal + Project-root Active Subject predicate, regardless of Container or owner. E654 tests that predicate, rejects a Goal Form resolving elsewhere or an unresolved Active Subject, and confirms a non-Goal Form does not qualify. The fixed `-1` Tier cannot be raised to satisfy an ordering edge; other graph-ordering exceptions remain.

R927's remaining `>=1` accepted Requirement Goal per Project coverage condition is distinct from R2132's Tier rule and is retained without its unsupported ownership clauses or restrictions on other Goals. Its Summary “Let Operators Define Project Goals” no longer describes that Claim. The same-ID R927 preview from the prior packet is superseded and must not be adopted or assigned a different Summary. A proposed successor body with an accurate Summary is in `project-goal-coverage-successor.txt`; it has an explicit root-allocated-ID placeholder. `project-goal-coverage-reference-plan.tsv` pins the current R927 predecessor and identifies the single active incoming unversioned relation in R947. The plan preserves CA-R-927@41 as history, moves the coverage Claim to a fresh ID, updates R947's incoming reference to that ID, preserves archived CA-R-930 history, and rebuilds derived projections after adoption. Root allocation of the successor ID remains necessary.

Other owner wording is handled without adding an owner or placement rule. CA-R-2688 and M461 previews remove only the Project Goal analogy and preserve external Operator ownership of the Project Declaration. D283's preview removes the obsolete Operator-owned Goal carve-out and does not replace it with an external-placement requirement. Current D292@35 and D342@29 apply only to filename and reference serialization for external carriers; their current Subject metadata still names Form `Project Goal`. D651@13 gives the external grammar precedence over ordinary filename defaults. None requires every Project-root Goal carrier to be external, and these legacy external predicates are not silently remapped to Form `Goal`. The sources remain unchanged and pinned in `goal-external-delivery-pins.tsv`. D292's `<OPERATOR_NAMES>` token continues to identify a registered Operator; it is not interpreted as Goal ownership or an Atom Author, which D657 says is not an Atom Property. No Carrier is moved and no universal internal/external placement is inferred.

CA-R-2706's preview replaces duplicate and overbroad range prose with a schema statement about one integer Tier and an optional Tier Label; its Formal Claim, including `>= -1`, is preserved. The combined R2125, R2131, and R2428 previews exclude only the exact Project-root Goal predicate from their general `>=0` minimums, regardless of owner; all ordinary ranges for other Atoms and Goals remain. Archived R2504 is not operative. The projected D482@27 owner clause has no Current source; the latest archived source is @26, so it is recorded as stale and receives no preview. Live E240@49 and E511@23 contain no Project Goal Operator-owner clause.

The Target Project ordering context remains distinct from ownership and containment. CA-R-2698@2 requires one immediate `IS_CONTAINED_BY` target; CA-R-2478@5 says containment does not imply ownership. No change to Project Declaration ownership is included.
