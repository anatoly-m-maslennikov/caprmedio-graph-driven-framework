## Decidable classification and admission procedure

Classify the **one complete independently replaceable Claim**, in its governed Subject and applicable authority context. Ignore the old tier label, filename length, source owner, reuse count, importance, precision, and breadth of Claim Scope as classification evidence. R/M/E/D identify contribution, not abstraction level. The same procedure applies to other admitted Atom roles after their existing Type restrictions and the Project Goal/Principle exceptions are resolved.

Use the following finite decision record for each proposed classification. Every answer must name the relevant Claim clause and a concrete reason or witness. Missing evidence produces **Unresolved**, never implicit Standard. These are decidable admission tests for an inspected Claim and declared witnesses; they do not assert that unrestricted English equivalence is machine-decidable.

1. **Admission and unit check.** Resolve the exact current revision, GOVERNS Subject, owner, Atom Scope, Claim Scope, role/Type, and governing boundary. Determine whether the complete Claim is one independently replaceable obligation. Independently replaceable components fail CA-R-918@8 / CA-E-384@7 and require existing atom-boundary review; a shared specification with its necessary preservation guard is not automatically two Claims. An unresolved referent, contradictory boundary, unadmitted Type, or unexplained source drift stops classification of that Atom.
2. **Concrete-choice test S.** Identify whether conformance requires a selected Carrier field/path/token/format, an execution technique or ordered realization procedure, or a selected test specimen/scenario. Give a replacement of that choice that preserves the represented semantic contract and its governing authority but changes conformance to this Claim. If the Claim's governing contribution is that choice, classify **Standard**. A whole-scope or reusable concrete syntax rule still passes S. A number or canonical Term merely used to express a semantic rule does not pass S: the rule must govern its concrete expression, procedure, or specimen. Necessary constraints inherited from higher authority remain guards on that realization and do not promote it.
3. **Constitutive-boundary test F.** If S is false, determine whether the Claim establishes or preserves the identity, purpose, authority ownership, fundamental separation, or semantic conservation conditions of its governed framework entities or mechanism. Cite that constitutive dependency: explain which meaning, owner, or preservation boundary would cease to hold if the Claim were negated. A Claim that qualifies is **Core**. The reason must concern that constitutive boundary, not that the Claim is useful everywhere or difficult to change. For example, settings being authoritative Operator selections for one instance/Project is constitutive; which selection policy obtains a mode is a further specification. An arbitrary shared behavioral choice is not made foundational by calling it an invariant.
4. **Independent-specification test G.** If S and F are false, identify a representation-independent contract over already constituted entities: permitted semantic choices, relationships, derived sets, behavior, or validation criteria. Establish (a) two materially different realizations that preserve the complete contract, and (b) a changed shared contract or countermodel that preserves its Core boundary while changing this Claim's conformance. Explain how the Claim can be accepted/revised/retired as its own authority unit, independently of a concrete realization and without duplicating its Core premise. Classify **General** only when both witnesses and the independent unit exist. An abstract recipe that fixes only an extensional semantic relationship, such as grouping by target role, qualifies; a procedure fixing serialization order or implementation steps passes S instead.
5. **Completeness and consistency check.** If none of S/F/G is justified, or independently replaceable contributions require different outcomes, return **Unresolved** with the exact missing proposition. A label-only assertion or a synonymous input such as `qualification=shared_specification` is not evidence. Resolve the uncertainty from existing authority and the above tests; ask the Operator one exact question only if a material choice still falls below 99%. Do not force a lowest-tier assignment, invent a General Atom, or silently change the accepted design.

The tests are ordered and mutually exclusive at the Claim level. S asks what concrete choice the Claim governs; F separates constitutive conditions from further specifications; G requires an independent policy and both separation witnesses. Admission can therefore terminate with a tier or a named failure instead of searching indefinitely for an automatic natural-language proof. The admission record consists of source identity/revision, governing boundary, Claim contribution, S/F/G reasoning, variation/counterexample evidence, old/new tier and rank, affected direct relations, and disposition. It is evidence for the existing Atom model, not a new governed Entity, field, Type, or Subject system.

## Independent witnesses for both boundaries

**Standard change preserves General.** Use existing R1430@1 and D374@1. State A encodes default strict and a U-specific casual override under TOML `authority_modes`; counterfactual state B uses `instance_modes`, with its corresponding decoder, for exactly the same default/override values. Both yield strict for P, casual for U, and the same active-Atom authority. R1430 and R1402 therefore have identical truth values. D374's current concrete condition accepts A and rejects B. The script checks equality of decoded semantic states, both selection results, and rejection by the unchanged D374 contract. The counterfactual proves a possible source-level Carrier change; it does not permit current Local Configuration or an Extension to rewrite D374.

**General change preserves Core.** Use R1402@3 and R1430@1. State A selects modes by default plus optional explicit override. Counterfactual state B requires an explicit selection for every target and has no default. Its selections remain Operator-owned behavior choices in one Framework Instance Settings Artifact for one instance/Project, so R1402 and the ownership partition META-REQU-675 remain true. R1430 rejects B because the required default is absent. This is a materially different shared selection specification, independent of its file encoding, with the foundational settings definition unchanged. Restoring the default returns to the current admitted policy. No General counterfactual is accepted as live authority.

**Independent second General case.** M265 computes the set of groups from target Content Roles. Current E446@2 owns twelve actual `evaluation_for` relations to R and D Atoms, producing `{Er, Ed}`. Ordered traversal, reverse traversal, and a target set are different realizations of the same relation. Choosing only the first target's role changes the grouping result while preserving the source target identities, Content Roles, and authority. This gives M265 a testable authority unit of its own. No duplicate Evaluation, new Content Role, intermediate Atom, or persisted target-role field is needed.
