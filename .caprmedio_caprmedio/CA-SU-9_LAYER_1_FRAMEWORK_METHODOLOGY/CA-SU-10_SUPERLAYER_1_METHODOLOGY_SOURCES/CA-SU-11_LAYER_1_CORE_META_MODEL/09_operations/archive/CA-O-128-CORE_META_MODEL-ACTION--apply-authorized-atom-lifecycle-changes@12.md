# Summary

Apply authorized Atom lifecycle changes

## Operation

This reusable Agentic Action applies only an exact admitted Create, identity-preserving Update, accepted Replace, model-admitted Change Status, or identity-preserving Move request. It returns effect/admission evidence, never selects a Workflow continuation or authorizes its own mutation.

### Inputs

- exact request kind and frozen boundary for exactly one Create target or one existing current target/predecessor, its complete proposed Carrier set or status/replacement mapping, target identity/locator, Revision, digest, destination and historical evidence.
- for Move, one existing current Atom with its exact source locator/digest, explicit destination mapping, expected Revision, destination collision/path/content-role checks and permission/effect admission.
- current applicable models, qualified role/type/status and Carrier/Relation validation authority, immutable Summary and identity rules, permissions and explicit effect admission. No required intermediate Atom Status or transition matrix is an admission condition. Preserve any selected adapter's sealed Initiative/delegated-apply conditions; preview alone grants no apply authority.
- for ordinary Update outside the instructed Subjects-only batch branch below, the exact O067 assessment/result and target/proposal/source evidence for that one target supplied by the assessment Step; for Replace, one active predecessor and its complete accepted set of >=1 distinct exact sealed prepared-new successor Carrier sets. Each prepared-new successor set contains complete sealed content, assigned identity, and destination; no preexisting-successor mode is admitted. Multiple Carriers or successors within that one approved replacement are not additional independent targets.
- admitted effect/recovery capabilities, definition bindings, Run/parent references, check expectations and available prior effect evidence, plus an independent canonical Journal append attempt. Missing effect/recovery capabilities or ordinary source, schema, identity, collision, expected-state or permission rules block effects; unavailable Journal recording is a diagnostic, not admission. An executor adapter is not Core authority.

### Behavior and outcomes

1. Reject multiple independent Create/current targets or predecessors as invalid before effects or reuse of an assessment. Bulk callers require separate individually admitted invocations/Runs; one target's O067 result never covers another target. Resolve the one target/predecessor and every required Carrier or replacement successor, and validate the whole selected boundary before effects: required current metadata, Summary, direct Relations, Role/Type placement, status model, destinations, historical references and applicable approval. Reject missing/ambiguous/repeated/self-referential targets, unsupported models, invalid content/status or collisions. Requested effects outside the frozen permission boundary return unauthorized; default to mutation-free preview until explicit apply admission.
2. Create: prove each destination absent and unique and each assigned identity unused against current allocation plus preserved all-history evidence; absent Active files alone are insufficient. Unassigned Drafts do not acquire invented IDs. Freeze complete content/targets/digests and the requested initial Status admitted by its qualified Role/Type Status model, without a required intermediate Status or transition matrix, under actual applicable authority; competing admission or changed absence invalidates apply rather than silently reallocating.
3. Ordinary Update outside the instructed Subjects-only batch branch: consume O067's exact identity-preserving result, not a reimplemented classifier. Preserve identity/Summary and admitted placement; an assessment requiring replacement cannot authorize this effect. Changed proposal, target or evidence returns reassessment-required with no mutation; changed definitions require separate revalidation. R1432 increments Version by exactly +1 for every actual same-ID update, including carrier_only/equivalent refinement and semantic_revision; replacement is not same-ID update. R1788 refreshes Updated At on every actual edit, including formatting; an exact no-op retains Version and Updated At. Retain exact prior Revision bytes as required history without another metadata edit to them.
4. Replace: validate the complete predecessor→successor-set intent without reducing it to a pair. Do not infer a successor from the predecessor or accept missing, partial, unsealed, colliding, or preexisting successor content. Reuse O051 once for the accepted replacement transition to materialize only the complete sealed prepared-new successor set; verify all named successors are Active before predecessor archival. Preserve its whole-Carrier/archive/status/time/@version and independently attempt its Journal observation, including explicit predecessor and every successor ID under R807; do not copy replacement history into Atom frontmatter or invent replacement Relations. A selected persistence capability unable to honor the complete approved boundary returns unsupported rather than truncating it.
5. Change Status: resolve the actual current Atom and complete qualified Content Role/Type status model under R1521/R1308. Accept any requested updated Status admitted by this exact bound Role/Type model, without a required intermediate Status or transition matrix. Its exact bound role model (including R1874 for Operations and R1875 for Analysis) supplies values; a more-specific declared Role/Type model overrides it, otherwise it inherits the role model without duplicated Type lists. Its most-specific Delivery rule supplies placement; only after that may D466's conditional Active/current or lowercase-status fallback apply. A missing, ambiguous or unsupported qualified model blocks unchanged; no role borrows another role's values. A same current value returns no-op. A containment cascade required by R1521 is composed by the calling Workflow from separate individually admitted invocations for the parent and each contained Atom's latest Revision; this Action still changes only its one bound Atom. References outside the parent Carrier tree and older archived Revisions are not cascade targets. Retain descendants within that tree when applying their model-admitted placement, including Archived. This source rule does not assert that a selected executor implements cascade composition. Archive only requests a status the same qualified model explicitly defines as archival; absent archival meaning returns missing-archival-model/unsupported unchanged, never maps Concern resolved/canceled or forces Archived. Preserve required identity/Summary/body/history/references, retain exact prior Revision bytes, and serialize only the admitted new current status, Version incremented by exactly +1 and actual edit time; independently attempt to append the transition observation to the shared Journal. Applicable archival uses one whole atomic Carrier transition and canonical @version suffix. Invalid models/Status values/destinations are blocked, never approximated by a universal list.
6. Move: validate the one exact current Atom and explicit destination mapping immediately before effect. Preserve its stable ID, Summary, Type, Substance, unrelated carriers and declared mapping; do not infer owner-dependent filename or reference changes. A same-location request is a no-op. A changed same-ID move advances Version by exactly +1, sets actual Updated At, and retains the exact pre-move current bytes as history. Destination collision, stale source, permission loss or unresolved semantic meaning leaves the source unchanged with a truthful blocked/uncertain outcome.
7. Freeze the complete mutation-free proposal and current preconditions. Immediately before any admitted effect recheck permission and all source/destination/assessment/definition bindings. Already satisfied valid state returns no-op with checks and Run evidence, not another effect/history event. Apply only the exact admitted boundary; preserve unrelated data. Partial publication is not successful set application.
8. Verify actual outputs, retained predecessor archives/references, moved source/destination and applicable source conditions. Independently attempt to append the actual change/Run observation to the canonical Journal. On effect/postcondition failure use only admitted bounded recovery, retaining actual completed/incomplete effects, immutable accepted events and recoverable evidence; incomplete/unverified recovery remains partial or failed. A Journal append failure is a recording diagnostic that does not invalidate a verified effect, make success non-complete or authorize replay. Retrying Journal delivery is not another Action execution.

## Details

The calling Workflow owns routing. This Action does not invoke O067, choose Replace, start a successor, reset retry allowance or broaden permission. O067 remains the classifier and O051 the accepted replacement-effect owner. Concrete MCP/Tool/path/seal adapters and implementation remain in their existing Engine/configuration units; current R1432/R1788 govern every actual same-ID update and exact no-op, while retained history preserves exact predecessor bytes.

Every actual invocation, including standalone and the referenced O051 execution, independently attempts to append its distinct Action Run identity, exact definition/input binding, parent Action/Step/Workflow lineage where applicable, start/terminal outcome and results/effects to the canonical Journal. Failed/canceled/no-op invocations record only actual observations without secrets or fictitious Artifact changes. An append failure remains a diagnostic and neither changes an actual effect outcome nor authorizes replay. A well-formed source definition does not prove that any effect or Run occurred.

### Instructed Subjects-only batch member

Bind this one exact packet member through the calling Workflow's actual instruction and existing Initiative/Operator authorization instead of a separate batch form/confirmation receipt or O067/O145/Analysis Report. At its existing operation retain normal exact target/source/draft/patch/layout, conditional-write, archive, Version/time and readback checks. No additional full-candidate validation/content-review round or public initial intent-hash metadata is a batch prerequisite; fresh native intent may be derived internally.

Publish only the declared Subjects plus N+1/actual time, preserving canonical ID, Summary, Type, original Status and unrelated bytes. For a pinned edit draft restore canonical ID/original Status from its temporary markers; current Active sources promote Active without changing generic non-Active semantics. Use exact predecessor archives and native failed-write handling. The caller composes commits/staging/promotion/graph, stops first failure/uncertainty, retains completed effects and leaves held/remaining sources unchanged, without automatic batch rollback/replay/retry/resume. Logging errors are truthful observations, not permission, proof or a completion gate. Ordinary Update assessment and new-Atom Draft rules remain unchanged.
