# Which legacy adaptation Claims belong to Project Configuration?

which preserved Claims **and** Actor policies replace the legacy Project Adaptation family under the accepted Project Configuration model?

## Evidence

META-REQU-687 defines Project Adaptation as PRMEDO authority that adds, specializes, narrows, **or** prohibits capabilities while leaving source Carriers unchanged. R-1218 names the accepted Project Configuration source; R-1375 prohibits weakening **or** replacing Core authority at **any** Local Tier, even with unchanged Core bytes. META-REQU-688 separately protects definition authority from Settings; META-REQU-689 permits Operator promotion into an Extension with exact provenance **and** no implicit source reconciliation.

## Principle check

CA-M-002 rejects a duplicate Project Configuration concept. CA-M-006 requires the source boundary **and** its consumers **to** agree. CA-R-1490 preserves the Settings separation **and** promotion conditions. the accepted rename does **not** itself settle the old PRMEDO admission list, the permissible narrowing boundary, **or** which existing authority already owns **every** unique condition.

## Disposition

preserve the legacy family until its complete Claims **and** incoming consumers are mapped **to** current owners. use the accepted Project Configuration name; do **not** introduce a compatibility alias as new authority, treat unchanged Core bytes as sufficient preservation, broaden the source-role domain, **or** discard provenance **and** reconciliation conditions during replacement.
