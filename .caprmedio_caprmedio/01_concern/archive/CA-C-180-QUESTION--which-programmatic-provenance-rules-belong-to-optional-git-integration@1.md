# Which programmatic provenance rules belong to optional Git integration?

which R-1095 guarantees remain general PROGRAMMATIC authority, **and** which belong **to** selected Git integration **without** independently owning the same recorded facts?

## Evidence

R-1095 requires intentionally redundant independent provenance systems, then distinguishes Git byte/tree/commit history from Journal action history. it also embeds concrete reconciliation states, exact commit bindings, release gates, **and** repair behavior. R-1466 makes Git integration optional Extension authority **and** rejects an independent Git source for the same Journal facts. different byte-history **and** Event-history responsibilities are valid; duplicate fact authority is **not**.

## Principle check

DRY forbids independently maintained authority for the same facts, **not** recoverable copies **or** complementary history. coherence requires optional Git integration **and** concrete provenance consumers **to** agree. information preservation prevents deleting the separate byte-history boundary, asynchronous guarantees, admission gates, **or** self-referential-digest safeguard.

## Disposition

preserve the complete R-1095 frontier pending a lossless general-versus-Extension map. do **not** assume that the current instance selects an Extension, turn Git into a Core prerequisite, remove provenance gates, **or** treat the whole Claim as a duplicate. map reconciliation behavior **to** O **and** its concrete encodings **to** D with exact retained consumers; no Git effect is authorized here.
