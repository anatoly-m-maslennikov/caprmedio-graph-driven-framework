# Which derivation rules are Methods rather than Actions?

which parts of the existing derivation **and** classification rules define reusable Implementation conventions, **and** which define the operational Actions that apply them?

## Evidence

M-114 mixes Term-definition selection **and** extraction rules with Generator instructions; M-120 combines graph-qualified registry derivation conventions with compilation **and** reporting steps; M-272 combines tier criteria with source resolution, classification, preservation review, **and** escalation. the Operator distinguishes what a Projection is, how it should be built, **and** the Process of building it. R-1340 permits Implementation choices **and** conventions as M; R-1344 assigns reusable operational behavior **to** O. imperative wording alone does **not** settle that boundary under R-1282.


R-1360 additionally embeds a restricted comparison grammar **and** normalization algorithm **in** a definition; M-240 supplies discovery **and** output behavior with the separate unresolved input-selection boundary recorded by C-126. E-403's former temporal-form criterion is absent from its current body, but the Claim still combines candidate eligibility, reporting, **and** mutation/publication exclusions. its generic Evaluation Subject **and** the candidate detection convention **in** M-238 need an exact checked-target **and** responsibility mapping under M-125. the removal of temporal nesting alone does **not** settle those remaining questions.


M-225 additionally prescribes mechanical Subject-index derivation, matching, prerequisite closure, ordering, **and** no-match behavior. its selection algorithm **may** remain M while an Action executes retrieval; that split **must not** duplicate the algorithm. META-REQU-744 separately distinguishes a reusable Implementation Method from a concrete Implementation Decision; its classification does **not** itself define an operational flow. preserve this distinction **when** resolving the execution boundary.

## Principle check

CA-M-002 rejects separately maintained copies of the same algorithm; CA-M-005 rejects a new Action **only** **to** change a role letter; CA-M-006 requires a consistent Method/Operations distinction; CA-R-1490 protects extraction, qualified graph ownership, evidence, **and** escalation constraints. R-1452 requires a justified Action boundary; R-1453 requires explicitly bound nodes for a Process.

## Disposition

preserve these Methods until the exact convention-versus-execution split is established from their complete Claims. reuse existing criteria **and** graph authority; do **not** turn **every** algorithm into a Process, leave a duplicate algorithm **in** both roles, **or** invent flow nodes **to** satisfy a structural check. each subsequent extraction requires its own preservation mapping.

## Shared PROGRAMMATIC Methods

M-110 selects Python but also describes selection materialization **and** admission stops. M-159 defines typed-interface conventions with exception/admission behavior. M-161 combines file/subprocess construction choices with precondition/effect/recovery behavior. M-164 combines selected quality profiles with adoption gates; M-165 combines measurement conventions with compare/accept flow; M-166 combines compatibility preservation with change admission. preserve every accepted selection, exception, support limit, **and** stop condition while mapping independent execution behavior **to** existing O authority.

M-158's object allocation/naming/composition conditions **and** M-160's deterministic-core/effect-boundary construction convention are **not** automatically O. imperative wording, numbered steps, **or** mentioning execution does **not** establish an independent Action. M-158 now uses bullets for independent conditions; M-160 retains its meaningful decision-before-effect ordering. role extraction still requires an explicit justified Action boundary, **not** a blanket Method-to-Process conversion.
