# Which current authority governs the Requirement Subject Catalog?

which exact current source-selection, grouping, ordering, parent-validation, **and** identity-display authority governs the Requirement Subject Catalog **before** its mixed R/M/E Carrier rules are reconciled?

## Evidence

CA-R-1059, CA-M-145, **and** CA-E-066 still specify a three-tier Requirement Catalog; M-145 reads `subject_scopes`, requires Core parents **to** be Principles **and** Standard parents **to** be Core, names a governed Subject catalog as the group-order source, **and** renders the short identity `REQU-NNN`. they also mix exact output placement **and** columns with source/graph rules **and** the rebuild procedure.

the current Subject carrier authority CA-D-269 **and** cardinality authority CA-R-1201 use direct `subjects.governs` **and** `subjects.depends_on`. CA-R-1442 admits General outside the Project; CA-R-680 has a different Project tier set. current Atom IDs include accepted canonical **and** legacy identities, which **must not** be rebound by an assumed short label. CA-C-111 records unresolved legacy Subject identity mappings **and** CA-C-117 records the absent authoritative Project Structure declarations. those gaps prevent certification of a complete canonical group/parent ordering from the old catalog alone.

## Principle check

CA-M-002 rejects a second independently maintained Subject **or** tier registry. CA-M-006 requires coherence with current authoritative selectors, Subject targets, identity, **and** contextual tiers. CA-M-005 rejects inventing another catalog merely **to** make the old output rule executable, **and** CA-R-1490 prevents dropping rows **or** historical identity evidence **to** hide unresolved mappings.

## Disposition

deferred under the Operator's uncertainty policy. retain the current Carriers as evidence rather than guessing a replacement group-order registry **or** treating numeric display aliases as canonical identity. first resolve the exact admitted Catalog input **and** validation authority; **then** separate the capability/source rules into R, operational rebuilding into O, concrete Carrier shape into D, **and** conformance cases into E. preserve all useful rows, direct authored parents, exact Summaries, atomic publication, reproducibility, **and** currentness checks. this is a bounded Catalog reconciliation question, **not** permission **to** modify other Projections **or** build a Tool now.
