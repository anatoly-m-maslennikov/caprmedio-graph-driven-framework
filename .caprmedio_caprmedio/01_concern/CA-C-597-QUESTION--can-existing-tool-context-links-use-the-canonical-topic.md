# Summary

Can existing Tool context links use the canonical topic?

## Question

May a Current Plan's existing DEPENDS_ON topic Tool use the canonical
Subject/Engineering/Tool path without claiming that Tool is its primary topic?

## Scope

Exact standalone Tool entries in Current Plan subjects.depends_on only.
Primary GOVERNS corrections require their separate source-specific evidence.

## Details

Bounded choice: yes. The dependency already names Tool. Qualifying that existing
context topic does not add a link or turn it into the governing thing. The
existing R1517/R1800 Tool topic and Candidate #7 supply its Engineering path.
Some task bodies discuss grammar, source mapping, release, images or other
primary things without repeating every contextual topic in prose. That alone
does not give the Tool dependency a different meaning or make it an execution.

Preserve each Plan's distinct governing Subject and all other topics, body,
status, scope, Tier and typed relations. Do not infer a Tool instance, new
Domain entity, Source Rule, permission or completion claim. This is not a
blanket rule for ambiguous role names such as Evaluation, Action or Workflow.
