# Which current graph owns feature realization bindings?

which current graph kind, source domain, **and** governing facts define the `feature_realization` Relation **without** duplicating Project Structure's Implementation Folder binding?

## Evidence

GOV-REQU-381 v18 maps a declared SPEC Feature Scope Unit **to** native Realization targets **without** making those targets Scope Units. the current model names delivered results Implementation, admits Scope Unit Type **and** Label separately, **and** places concrete authority **and** delivery paths **in** Project Structure. the Claim does **not** identify the graph kind owning its Relation Kind **or** settle whether SPEC Feature means a current classification, a Label, **or** a retired subset.

## Principle check

CA-M-002 prohibits an independently maintained second delivery binding; CA-M-006 requires graph-qualified Relation domains **and** current Terms; CA-R-1490 protects useful links **to** native Implementation. this is **not** a Scope Unit dependency merely because its source is a Scope Unit. replacing Feature with **every** Scope Unit would broaden the domain **without** resolving its original job.

## Disposition

preserve the source until its exact graph ownership **and** authoritative inputs are established. do **not** infer a forbidden cross-Scope dependency, turn native Implementation targets into Scope Units, invent a new graph kind, **or** retain a second authoritative copy of Project Structure. separate derived graph links from the facts that admit them.
