# Summary

Which existing Subjects best describe multi-topic Plan work?

## Question

When a legacy Plan governs both a thing and its update activity, which existing
Subject describes its objective without inventing a new Domain kind or property?

## Scope

The four Plans-77 review lanes, covering sixty-two Current Plans. This records
bounded Subject choices, not new execution authority or content migration.

## Details

Use the body-grounded governed thing as the single GOVERNS target. Preserve
unresolved predecessor IDs and old activity labels literally in DEPENDS_ON for
later mapping; they are not declared new kinds. Do not make a named work
description an actual Occurrent instance merely by adding a path prefix.

Apply these root corrections to the supported proposals:

- P920 concerns Project Configuration Atoms, not the Framework Settings TOML
  property. Govern Atom and retain the relevant Scope Unit context.
- P936 and P940 concern the canonical ca Skill. Govern Engineering/Skill and
  keep runtime Tool context separately.
- P944 freezes a defined heterogeneous frontier. Use a named Selection, retain
  Carrier context and Project.Settings, and do not substitute Framework Settings.
- P909 concerns a defined set of Content Role and Type authority. Use its named
  Selection and the existing Atom/Content Role topic. Do not create Atom.Content
  or Atom.Type as new dependent-property paths.
- P921 produces a report Projection. Use Projection, with Applicable Methodology
  as context; do not create a Conflict property on that Projection Type.
- P925 normalizes Project Atoms. Govern Atom, retaining Project as context.
- P949 governs its defined disposition set; its report input is a Projection,
  not an unapproved Conflict property.

Other supported existing-kind and named-selection choices retain their exact
source-body evidence in the root-approved manifests. A named Selection chooses
existing things; it does not create a new Domain kind or property.

The initially held P083, P108, P109, P112, P113, P908, P922, P939, P942, P943,
P946 and P950 stay unchanged in this increment. Their mapping or conflict
dispositions remain open; a held proposal is not a completed migration.

It adds no approval gate, does not reinterpret old task bodies as new active
RMED rules, and does not authorize PROGRAMMATIC implementation.
