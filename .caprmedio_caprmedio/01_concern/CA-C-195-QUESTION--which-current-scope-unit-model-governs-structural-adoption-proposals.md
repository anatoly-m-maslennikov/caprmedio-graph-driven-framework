# Which current Scope Unit model governs structural adoption proposals?

which current Scope Unit classification **and** proposal Carrier should M-102 use **when** turning native Implementation observations into proposals?

## Evidence

M-101 preserves observed directories, files, modules **and** dependencies **without** making authority. M-102 proposes Area, Feature **and** Module drafts from folder/file shapes **and** produces a CRMED draft set. R-1483/R-1484 now establish accepted Scope Units through Project Structure declarations independently of Goals **and** materialization. a folder shape alone cannot determine the intended Name, Type, Label, parent **or** binding, **and** a CRMED draft alone does **not** establish that declaration.

## Principle check

DRY requires one accepted structural source. coherence separates observation, proposal **and** accepted declaration. information preservation protects the useful as-is Inventory, explicit ambiguity, Operator review **and** complete proposed relationships. these do **not** choose whether the legacy labels are optional heuristics, selected defaults **or** universal taxonomy, **or** identify an admitted Carrier for the proposal.

## Disposition

preserve M-101/M-102 **and** the independently useful Inventory while resolving the heuristic **and** proposal Carrier against current structure authority. reuse C-117 for actual declarations **and** C-141 for Method/Action extraction. do **not** silently accept a filesystem-derived tree, discard ambiguous observations, rewrite accepted structure, widen the draft-role set **or** change Summary identity by a lexical rename.
