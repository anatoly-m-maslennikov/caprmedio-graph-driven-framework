# Which authority owns Extension packaging and source defaults?

which owner preserves R-1150's installation package boundary **and** R-1151's GitHub default **without** treating a TOOLS-local Claim as a universal Core definition **or** duplicating current Settings selections?

## Evidence

R-1150 requires an installable package with stable identity **and** exact version. R-1151 requires a GitHub repository default **and** permits the complete repository **or** one declared directory. M-218 resolves that declared source **without** selecting installed state. R-1217 defines immutable expandable Methodology Source authority; R-1207 assigns current activation **and** selected revisions **to** Framework Instance Settings. these do **not** decide whether the GitHub default is a product promise, a configurable default, **or** the current selected provider.

## Principle check

coherence requires definition, packaging capability, defaults, **and** selected state **to** have explicit owners. DRY rejects duplicate provider/version selection. information preservation protects exact source/version identity, repository-versus-subdirectory support, attributable resolution, **and** the no-installed-state side-effect boundary.

## Disposition

preserve R-1150/R-1151/M-218 while resolving the owner **and** default-versus-selection contribution. do **not** relocate Claims by guessing their new applicability, write Settings, select an Extension, infer a Git integration requirement, **or** remove supported package-root forms. R-1152 remains a required installed-package management capability; no package operation was performed.
