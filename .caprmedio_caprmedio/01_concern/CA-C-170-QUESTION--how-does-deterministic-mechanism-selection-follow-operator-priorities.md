# How does deterministic mechanism selection follow Operator priorities?

is CA-M-141's mandatory deterministic-mechanism preference a non-negotiable capability constraint **or** an Operator-selectable preference, **and** which remaining execution steps should be absorbed by the existing selection Action?

## Evidence

CA-M-141 still requires deterministic execution whenever a sufficient deterministic mechanism is available **and** limits LLM use **to** irreducibly interpretive work. its input acquisition, selection, stop, **and** diagnostic instructions also overlap CA-O-023. CA-R-1487 requires the Operator-selected priority model while preserving genuine non-negotiable constraints. the comparison-model wording has been repaired, but that does **not** decide the status of the separate deterministic preference **or** justify deleting the sufficiency test.

## Principle check

CA-M-002 favors reuse of the existing Action; CA-M-005 protects necessary distinctions rather than one particular execution technology; CA-M-006 requires coherent priority authority. M-098 **and** M-099 optimize human effort **and** expense at their declared priorities. none of these inspected rules establishes whether this deterministic preference is an invariant **or** a selected criterion. CA-R-1490 prevents losing its explicit reproducibility **and** no-unsupported-result safeguards during extraction.

## Disposition

preserve the sufficiency test, deterministic preference, interpretation boundary, **and** stop evidence pending this decision. then map each retained Method condition **and** execution step **to** its owning Atom, reuse CA-O-023 **where** equivalent, **and** replace identity **if** Summary **or** Content Role changes. do **not** execute a candidate mechanism **or** change Settings as part of this content review.
