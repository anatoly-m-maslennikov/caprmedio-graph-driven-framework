# What authority admits Extension application bindings?

which current Type **and** graph-qualified Relation authority admits the separate Extension application binding described by META-REQU-174?

## Evidence

META-REQU-174 v13 calls an Extension an owned capability package **and** its application a separate binding Atom relating the Extension **to** target Scope Units. it explicitly excludes current activation **and** selected Extension Revision ownership from that binding. R-1217 defines an Extension as an immutable Methodology Source under R-1375's expansion boundary; R-1207 **and** META-REQU-163 preserve current selection **in** Framework Instance Settings. the binding's Atom Type, Content Role, qualified target, **and** admitted Relation endpoints are **not** supplied by META-REQU-174 itself.

## Principle check

CA-M-002 prohibits a second activation registry; CA-M-005 requires a distinct job for another binding Artifact; CA-M-006 requires explicit graph-qualified endpoints; CA-R-1490 protects source provenance **and** the separation of definition from current selection. the absence of a registered binding **in** this Claim alone is **not** evidence that **all** application information is redundant.

## Disposition

preserve the source while locating **or** deciding the exact binding authority. do **not** invent a new Type, infer inter-Scope dependency edges, convert multiple referenced targets into a composite Claim Scope Unit, **or** duplicate current Settings selections. retire **or** replace the Claim **only** **after** its unique permitted application information has a proven owner.
