# Which Methodology portability and session Claims belong to Engine authority?

which preserved Methodology Claims govern reusable model neutrality, **and** which require concrete FRAMEWORK_ENGINE capabilities?

## Evidence

METHODOLOGY-REQU-493 promises macOS, Linux, Windows, **and** WSL support plus platform-behavior allocation. REQU-495 adds language-specific rule allocation; REQU-496 adds provider-specific Extension behavior **and** operation by a capable LLM. those are **not** proven duplicates of META-REQU-106's implementation-neutral Core model. their parent REQU-506 broadly assigns cross-platform behavior **to** FRAMEWORK_METHODOLOGY. REQU-507 requires session initialization **and** REQU-508 requires equivalent natural-language routing; these are runtime capabilities, **not** model definitions. REQU-509's envelope boundary is already C-167.

## Principle check

CA-M-002 requires reuse **only** for equivalent authority; CA-M-006 requires coherent ownership; CA-R-1490 prevents losing platform, language, provider, **or** session promises during deduplication. C-117 leaves structural declarations unresolved **and** C-119 requires preserving owner-dependent applicability on relocation. a physical move alone cannot certify the correct new parent, declared scope, **and** preserved target.

## Disposition

preserve the named capability Claims **and** their support set. establish their model-versus-runtime ownership map **and** exact surviving Relations **before** relocation **or** consolidation. no platform support is considered tested, no Actor gains permission merely from capability, **and** no hook **or** session integration is installed as part of this review.
