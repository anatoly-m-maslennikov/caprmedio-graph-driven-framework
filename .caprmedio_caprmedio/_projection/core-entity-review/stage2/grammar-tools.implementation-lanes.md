# CA-P-1965 implementation lanes

This is a derived implementation boundary for the accepted grammar-aware Tool contract. It adds no grammar, native endpoint registry, migration API, or source authority.

## Shared API

The new `201_TOOLS/subject_notation.py` has:

- `get_profile(name="legacy")`: strict named-profile lookup returning an immutable profile with `name`, `separators`, `bearer_separator` and five immutable grammar pins. Unknown/malformed supplied values fail.
- `parse_subject(value, *, subject_profile="legacy")`: returns a list of `(component, preceding_separator)` tuples; first separator is None. Preserve legacy dotted components and existing whitespace handling. Approved separates slash, dot and colon.
- `profile_evidence(name="legacy")`: fresh JSON-compatible dict with exactly `grammar_pins` and `native_admission: "not_performed"`. Every pin has atom_id/version/path/sha256, matching `tool-grammar.packet.json`.
- `SubjectNotationError`: ValueError subtype with a stable `code` and useful message, wrapped by each existing Tool/graph error class.

Profiles are explicit; absence is normalized to legacy by callers, not detected from the string. Shared parsing rejects empty/malformed segments, `@`, unsupported escapes and unsupported selector/conjunction expressions. Do not invent a Term vocabulary or canonical endpoint proof. Native relation admission is outside this API. Grammar pins are evidence about this implementation, not filesystem assumptions about a caller's Project.

## Integration requirements

Search CLI exposes `--subject-profile legacy|approved`; supplied Subject-only options without `--subject` reject. Descriptions document the selected profile and output evidence.

Load update payload once before extracting items. Subject-only root must be a mapping with exactly atoms and optional subject_profile; do not let the generic `_items` helper discard unknown root keys. Explicit null/unknown profiles fail. Mixed modes and Subject-only apply still fail. Generic routes keep their existing behavior and guard.

Preview validates every direct source Subject and every proposed direct Subject under one selected profile around the existing complete-carrier validator. Evidence is part of the sealed preview digest, including no-op results. Preserve pin/stale/no-follow/duplicate/CRLF/Unicode/body/unknown-field guarantees.

Graph profile selection is keyword-only/internal and legacy by default. Approved slash creates no native IS_BORNE_BY or NARROWER_THAN fact; dot and colon retain admitted-direction syntax. Preserve full prefixes, namespaces and evidence. The approved current-Core provider checks the exact current five grammar pins before use; this is source-pin binding, not endpoint/native admission. Retain the old extractor D269/R1194 evidence unchanged. Do not rewrite frozen Step1 modules/outputs, add public generator selectors, or silently switch native admission consumers.

Use uv offline with cached PyYAML 6.0.3 and pydantic 2.13.5 where needed. Scratch, test fixtures and caches are under .caprmedio_tmp. Run unittest suites; Root keeps final independent acceptance under CA-P-1975. Tests prove literal independently authored expected output, not values generated by the producer.
