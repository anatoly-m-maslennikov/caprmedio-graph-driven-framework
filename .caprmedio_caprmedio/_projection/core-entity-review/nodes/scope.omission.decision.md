# Operator direction: omit only the default Substance Scope

Derived candidate direction recorded on 2026-10-10 in Asia/Tbilisi, after the Substance naming decision. This is not an adopted Core rule or Subject migration approval.

The Operator said:

> Substance scope can be omitted if
> - it about the whole subject
> - AND it's about the whole scope unit that owns the atom

For the candidate content model, an absent explicit Substance Scope resolves to the full governed Subject within the full Scope Unit owning the Atom. Both conditions must hold. If either the Subject coverage or the owning-unit coverage is restricted, the Substance Scope must be explicit.

Omission is a contextual default, not absence of Scope, global applicability outside ownership, permission to infer a new Scope Unit, or removal of owning Scope Unit metadata. Do not confuse a Subject restriction with Atom ownership or a content target with a structural-parent edge.

This direction supplements the earlier pinned Substance decision record. Latest Operator input wins. Preserve the current Core source model and every old identity/pin; review the resulting candidate mapping and required future schema/authoring changes before any migration.
