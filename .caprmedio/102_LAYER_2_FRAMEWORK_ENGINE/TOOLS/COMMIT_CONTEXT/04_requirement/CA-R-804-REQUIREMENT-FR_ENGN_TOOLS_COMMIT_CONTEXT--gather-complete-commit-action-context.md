# Gather complete commit action context

`COMMIT_CONTEXT` must be independently invocable, strictly read-only, and operationally loose about graph correctness. From one Hook trigger, it validates the adapter, source-event, trigger, repository, and structured LLM-session candidate identities; reads the changed project path and observable Git states; and deterministically resolves exactly one file or folder subject identity and its `ADD`, `MOVE`, `UPDATE`, `MOVE+UPDATE`, or `REMOVE` change set. A folder context seals its complete ordered Git-trackable entry set and aggregate digest while remaining one subject. It is a logger context Finder, not a graph Checker. An unrelated missing target, duplicate identity, broken relation, invalid tier direction, or other graph defect must not block recording the changed project path.

The Finder may inspect an Atom and the relation registry only to decorate the log with relation sources that resolve unambiguously. Ordinary files and folder subjects require no graph resolution and may carry an empty source list. Unresolved, ambiguous, stale, unknown, duplicated, or otherwise invalid relations become non-blocking diagnostics; successfully resolved sources remain typed, ordered, and revision-bound. Graph-wide correctness belongs to separate Checker Tools. An Atom keeps its declared version. A non-Atom file or folder receives a deterministic logger-owned revision from accepted Git and Journal history without editing the subject. The Finder still resolves a subject transition whose before-state or after-state is draft, done, solved, archived, or another registered inactive lifecycle. It reads only the staged, working, committed, Journal, and repository apply-lease state required for that action. The same trigger and unchanged subject frontier must yield the same action and event identities. Before-state data may exist inside this sealed ephemeral context only to classify the change; it must not be copied into the Work Journal event.

The Finder seals the canonical structured `governed_project_change` event: stable event and action identities, adapter and source-event provenance, file-or-folder subject kind, structured `llm_session` with canonical `app` and host `uuid`, author, one timezone-qualified `occurred_at` and local calendar date, configured timezone, `action_type`, best-effort ordered `sources`, singular resulting `result`, and `previous_result_event` when one exists. It resolves LLM-session values through the registered application adapter, preferring an explicit validated invocation value, and fails closed rather than guess when required operational provenance is absent or ambiguous. It resolves the author and event time exactly once; all downstream Tools must use these sealed author, timezone, `occurred_at`, and local-date values without recomputing them. The sealed values and event identity must remain unchanged on retry; `<app>:<uuid>:<occurred_at>` is only a derived presentation.

When a non-`ADD` subject has no accepted prior result event, the Finder also seals a candidate `recovered` baseline record and the exact evidence required by the recovery rule. It predicts the complete ordered Journal sidecar record set, every target partition, repository lease availability, and the Git message Projection governed by the canonical commit-message rule without storing that message as Journal authority. An explicit author must be a full GitHub username; when omitted, the Finder resolves the current operator's full GitHub username and fails closed if it cannot do so unambiguously. It derives `MOVE` from a Structural-location change and `UPDATE` from a content, filename, or other governed carrier-state change, emitting `MOVE+UPDATE` when both flags are true. It must not edit governed files, copy LLM-session event provenance into Atoms or Projections, append Journals or Projections, acquire an apply lease, change the Git index, or create or rewrite Git history. Context gathering is mandatory, but `COMMIT_CHANGE_SET` may invoke the same deterministic logic internally instead of requiring a separate standalone call.
