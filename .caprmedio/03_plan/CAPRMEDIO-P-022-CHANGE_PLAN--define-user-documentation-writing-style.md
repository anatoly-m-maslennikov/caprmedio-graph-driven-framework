# Define the User Documentation writing style

1. [ ] Inventory current FRAMEWORK_USER_DOCUMENTATION authority and native user-facing documents, including README material, guides, examples, explanations, and generated documentation views.
2. [ ] Define a distinct user-documentation style that is looser, more human, less dense, and written with simpler language than the Atom style while remaining accurate to the governed source meaning.
3. [ ] Place the governing style in FRAMEWORK_USER_DOCUMENTATION Method and treat the concrete user-facing documents and their realized voice as native Implementation.
4. [ ] Permit explanation, examples, narrative transitions, and audience-appropriate repetition that would be unnecessary in an Atom, without allowing User Documentation to establish or change RMED authority.
5. [ ] Create or revise independently checkable Evaluation Atoms for readability, human tone, source fidelity, and absence of unsupported claims, keeping one bounded Evaluation case in each Atom.
6. [ ] Update user-documentation authoring interfaces and templates to call the accepted Method without importing the stricter Atom style as their default voice.
7. [ ] Apply the style to current user-facing Implementation, rebuild affected Projections, and verify that every document remains traceable to its governed sources without becoming a second authority surface.
