# Define the Atom writing style

1. [ ] Inventory active and draft FRAMEWORK_METHODOLOGY Requirement, Method, Evaluation, and Delivery Atoms that govern Atom wording, authoring, readability, context, duplication, and carrier mechanics.
2. [ ] Define the Bootstrap Seed as the initial minimal owner of Atom-writing guidance needed to create and understand FRAMEWORK_METHODOLOGY without active recursion, then define the handoff through which FRAMEWORK_METHODOLOGY Method becomes the maintained owner.
3. [ ] Establish the role boundary: Requirement owns the meaning that must be present; FRAMEWORK_METHODOLOGY Method owns how Atom meaning is written; Evaluation owns how preservation and clarity are checked; GOV owns mechanical filename, frontmatter, and placement rules.
4. [ ] Create or revise the minimum tiered FRAMEWORK_METHODOLOGY Method Atoms needed to govern a strict, compact, exact, and context-complete Atom style: direct claims, simple words, one definition per term, no duplicate explanation, and the least text from which intended meaning can be recovered.
5. [ ] Keep every Atom in its own Content role when it follows the writing Method; applying a style never reclassifies Concern, Analysis, Plan, RMED, Implementation, or Ops prose as Method or Implementation.
6. [ ] Move each existing Atom-writing rule to its correct Method owner without moving semantic obligations out of Requirement or mechanical carrier rules out of GOV.
7. [ ] Create or revise independently checkable Evaluation Atoms for the accepted Atom-writing Methods, keeping one bounded Evaluation case in each Atom.
8. [ ] Update Skills and authoring guidance to call the accepted Methods without copying their authority, then verify that the Bootstrap Seed remains minimal and no active writing-style rule has two owners.
